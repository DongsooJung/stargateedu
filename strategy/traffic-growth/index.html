1. Executive Summary

현재 STARGATE는 프로젝트와 대시보드 자산이 많아 포트폴리오 신뢰도는 높지만, 검색 이용자가 들어올 명확한 주제별 진입점과 콘텐츠 생산 루프가 약하다. 따라서 신규 기능 추가보다 기존 자산을 검색 가능한 콘텐츠와 랜딩페이지로 재조직하는 것이 우선이다.

www의 역할

전환 허브로 집중한다. 연구·대시보드·교육·B2B 프로젝트를 신뢰 자산으로 보여주고, 상담·상품·제휴·수주로 연결한다.

blog의 역할

검색·콘텐츠 엔진으로 집중한다. 사용자가 실제로 검색하는 질문에 답하고 관련 대시보드와 서비스로 이동시킨다.

핵심 한 줄: 블로그에서 질문에 답하고 → 대시보드에서 증명하고 → STARGATE에서 구매·상담·수주로 전환한다.

11. 주간 운영 루프

  1. 월: Search Console/Naver의 신규 Query와 5~20위 페이지 확인
  2. 화–목: 검색형 콘텐츠 2~3건 작성 및 기존 대시보드 연결
  3. 금: 제목·CTR·내부링크·CTA 보정
  4. 주말: 다음 주 콘텐츠 우선순위를 데이터 기반으로 결정
운영 원칙: 새 프로젝트를 계속 추가하기보다, 이미 구축한 프로젝트를 검색 가능한 콘텐츠로 재활용하는 비중을 높인다.

12. 결론

STARGATE의 경쟁력은 일반 블로그처럼 글만 생산하는 데 있지 않다. 데이터 → 분석글 → 인터랙티브 대시보드 → 서비스를 하나의 경로로 연결할 수 있다는 점이 차별점이다. 90일 동안 이 연결 구조와 검색 측정 체계를 먼저 완성하면, 이후 광고·SNS·제휴 유입도 더 높은 전환효율로 흡수할 수 있다.
