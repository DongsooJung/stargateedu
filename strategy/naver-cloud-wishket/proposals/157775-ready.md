## 핵심 제안 포지셔닝
기존 GCP 기반 운영 환경을 존중하면서 AI Agent를 독립 서비스 계층으로 분리합니다. 특정 클라우드 전환을 전제로 하지 않고, Agent 실행 흐름·API 계약·권한·실패복구·로그·비용을 운영 가능한 수준으로 설계합니다. 한국어 생성·분석이나 국내 클라우드 요구가 생기면 CLOVA Studio를 선택형 모델 계층으로 비교 제안합니다.

## 지원 메시지
안녕하세요. 마케팅 자동화 플랫폼의 2차 오픈 이후 확장·운영 단계에서 AI Agent를 개발하고 기존 서비스와 안정적으로 연동하는 프로젝트로 이해했습니다.

저는 이번 과업을 단순 LLM 기능 추가가 아니라, 실제 운영 서비스 안에서 Agent가 안전하게 업무를 실행하도록 만드는 문제로 보고 있습니다. 기존 GCP 환경은 유지하되 AI Agent를 독립 서비스 계층으로 분리하고, 기존 마케팅 데이터와 내부/외부 API를 명확한 인터페이스로 연결하는 구조를 우선 제안드립니다.

구현 단계에서는 ① Agent가 수행할 액션과 승인 범위 정의, ② API/데이터 연동 및 권한 분리, ③ 프롬프트·도구 호출·실패복구 로직, ④ 실행 로그와 비용/성능 모니터링, ⑤ 운영 데이터 기반 평가·고도화 순으로 접근하겠습니다. 특히 자동화율만 높이는 것보다 잘못된 액션을 방지하고 사람이 개입해야 할 지점을 명확히 설계하는 것이 중요하다고 봅니다.

한국어 생성·분석 또는 국내 클라우드 요구가 있는 영역은 CLOVA Studio를 선택지로 비교할 수 있지만, 기존 GCP를 무리하게 대체하지 않고 현재 시스템과 성능·비용·운영성을 기준으로 가장 적합한 구성을 결정하겠습니다.

초기 합류 후에는 현재 아키텍처와 Agent 연동 지점을 빠르게 파악하고, 가장 ROI가 높은 1~2개 자동화 시나리오부터 안정화한 뒤 단계적으로 기능을 확장하겠습니다.

## 첫 미팅 핵심 질문
1. 현재 GCP 아키텍처에서 Agent가 연결될 서비스와 API는 무엇인지
2. Agent가 조회만 하는지, 광고/CRM/캠페인 실행까지 직접 액션하는지
3. 승인 없이 자동 실행 가능한 업무와 human-in-the-loop가 필요한 업무의 경계
4. 현재 사용 중인 LLM/Agent framework 또는 선호 기술이 있는지
5. 운영 KPI가 처리시간, 전환율, 작업 자동화율, 비용 절감 중 무엇인지
6. 실패 시 재시도·롤백·알림 정책과 SLA 요구사항
7. 고객/마케팅 데이터의 개인정보·보안 제약

## 제안 시 강조할 것
- GCP → NCP 전환 프로젝트처럼 말하지 않는다.
- 'Agent를 만들 수 있다'보다 '운영 가능한 Agent를 만든다'를 강조한다.
- API 실패, 잘못된 action, 권한, 비용 폭증에 대한 통제를 선제적으로 설명한다.
- CLOVA Studio는 한국어/국내 클라우드 필요 구간의 선택형 옵션으로만 제시한다.
