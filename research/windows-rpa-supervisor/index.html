Current Implementation

지금까지 구현된 핵심

웹 서버가 Windows를 직접 조작하지 않고 실제 PC에서 로컬 에이전트가 작업을 수행합니다.

01

Windows Local Agent

FastAPI + pywinauto(UIA) + pyautogui. 프로그램 실행, 창 포커스, 버튼 클릭, 텍스트 입력, 단축키, 대기, 스크린샷, 창 목록 조회를 지원합니다.

02

보안·직렬 실행

Bearer Token, 실행 파일 allowlist, CORS 제한, 동시 실행 Lock, 실행 수/대기 시간 제한, JSONL 감사 로그를 적용했습니다.

03

관리자 콘솔

스타게이트 관리자 화면에서 에이전트 상태 확인, 템플릿 실행, Action JSON 편집, 결과 및 실행 기록 조회 구조를 구성했습니다.

04

실행 예시 2종

메모장 자동 입력·저장과 계산기 자동 계산을 통해 Windows UI Automation 실행 흐름을 검증하는 샘플을 포함했습니다.

05

모바일 Supervisor

PC 온라인 상태, 최근 실행 기록, 승인 대기 목록, 승인·거절, 감독 서버 설정을 모바일 우선 UI로 구현했습니다.

06

중앙 Relay 설계

모바일이 로컬 PC 포트에 직접 접근하지 않고 HTTPS Relay/Orchestrator를 통해 작업 큐와 승인 정책을 거치는 구조입니다.

Mobile Supervision

휴대폰은 원격 마우스가 아니라 관제·승인 장치

모바일을 직접 PC 제어기로 만들기보다 자동화의 상태·위험·승인을 감독하는 역할로 설계합니다.

온라인 상태

PC heartbeat와 agent_id를 사용해 대표실-PC, 연구-PC 등 다수 장비의 연결 상태를 표시합니다.

실행 현황

queued, running, waiting_approval, success, failed, cancelled 상태를 모바일에서 즉시 확인합니다.

승인·거절

고위험 작업은 모바일에서 승인 전까지 진행하지 않고 대기합니다.

스크린샷 감독

실행 중 화면과 실패 직전 화면을 서버에 업로드해 모바일에서 확인합니다.

푸시 알림

승인 필요, 실패, 완료, 장시간 정지 등의 이벤트를 모바일 알림으로 전달합니다.

Emergency Stop

모든 자동화를 중단하고 신규 실행을 잠그는 긴급 정지 버튼을 둡니다.

Security Policy

업무 위험도에 따른 승인 정책

Windows Agent의 8765 포트를 인터넷에 직접 노출하지 않고 Relay/VPN을 사용합니다.

LOW · 자동 허용상태 조회, 창 목록, 로그 조회, 스크린샷 등 읽기 중심 작업.
MEDIUM · 조건부문서 생성, 파일 저장, 브라우저 입력, 내부 업로드 등 변경 작업.
HIGH · 모바일 승인 필수삭제, 결제, 계정 변경, 외부 메시지·메일 전송, 외부 공개 작업.
통제 항목적용 원칙
Agent 네트워크기본 127.0.0.1 바인딩, 인터넷 직접 노출 금지
인증Bearer Token → 향후 short-lived signed token
실행 파일allowlist 기반 승인된 executable만 실행
동시 실행한 PC 화면 제어는 단일 consumer/lock으로 직렬화
비밀값Vault에서 주입, Action JSON에 평문 저장 금지
감사 로그누가·언제·어떤 명령·승인·결과를 남겼는지 저장
